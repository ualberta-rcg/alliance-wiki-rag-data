A job submission web page should appear in your browser.  Configure the resources required for your interactive desktop session and click on ''Launch'' or ''Start''.  If either accelerated graphics or computations will be conducted from within your desktop session, be sure to specify a GPU resource.  Load an Ansys module on the desktop.  If you started a JuypterLab powered desktop, this can be done by clicking on the left-hand menu, or if you started an OnDemand desktop manually, type <code>module load ansys/version</code> on the command line.  To start one of the common Ansys programs such as Fluent, CFX, Workbench, and so forth, refer to the following section which provides advice for setting environment variables and arguments required by VirtualGL or Mesa-based graphical environments, depending on whether a node with a GPU resource was specified or not.  

=== Fluent === <!--T:4--> 


<!--T:5-->
To start Ansys Fluent from the command line on an OnDemand desktop, open a terminal window and run


<!--T:6-->
::: <code>module load StdEnv/2023 ansys/2025R2.04</code>
::: <code>fluent</code>


<!--T:7-->
When the Fluent Launcher popup selector panel appears, click on the ''Environment'' tab and copy/paste the following environment variable settings, depending on whether you started your OnDemand session with a GPU for graphical acceleration. Do not include the text in parentheses as these are comments, and do not put <code>export</code> in front of any variable name.  If the graphics console window becomes corrupted when starting the GUI, restart Fluent setting <code>HOOPS_PICTURE=null</code> to disable the creation of the graphics panel. 


<!--T:8-->
<b>Compute node (no GPU requested)</b>


<!--T:9-->
::: <code>I_MPI_HYDRA_BOOTSTRAP=ssh</code> &nbsp;&nbsp;&nbsp;&nbsp; (required on Nibi w/ intelmpi)
::: <code>HOOPS_PICTURE=opengl2-mesa</code> &nbsp;&nbsp; (version 2025R1 or newer)
::: <code>HOOPS_PICTURE=x11/lin</code> &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;   (version 2024R2.04 or older)
::: Click on the ''Start'' button.


<!--T:10-->
<b>Compute node (with GPU requested)</b>


<!--T:11-->
To use hardware accelerated graphics with Fluent on Nibi, choose a t4 (15GB) from the GPU selector pulldown list for your OnDemand desktop session.  Doing this ensures that the environment variables used by VirtualGL to enable accelerated OpenGL graphics calls are automatically set up inside your desktop environment for the current session.  Once your desktop appears, open a terminal window and start Workbench as follows
::: <code>I_MPI_HYDRA_BOOTSTRAP=ssh</code> &nbsp;&nbsp;&nbsp;&nbsp; (required on Nibi)
::: <code>HOOPS_PICTURE=opengl2</code> &nbsp;&nbsp; (version 2025R1 or newer)
::: <code>HOOPS_PICTURE=opengl</code> &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; (version 2024R2.04 or older)
::: Click on the ''Start'' button.


<!--T:12-->
NOTE: When running Fluent on Nibi, the environment variable <code>I_MPI_HYDRA_BOOTSTRAP=ssh</code> must be manually set; otherwise, Fluent will crash when started inside OOD Compute Desktop sessions when intelmpi is used.  Error output such as the following will be created.  Should this occur, completely exit Fluent, cleanly shut down Workbench and start over.

=== Workbench === <!--T:19--> 


<!--T:20-->
This section shows how to start Workbench (and optionally Fluent) on either an OnDemand desktop or a JupyterLab desktop.

==== OnDemand desktop ==== <!--T:21--> 


<!--T:22-->
<b>Compute node (no GPU requested) or basic desktop</b>


<!--T:23-->
If accelerated graphics are not required for your desktop session, specify ''GPU Node'' to select a compute node without a GPU for your OOD session.  Doing this uses Mesa software emulation for opengl calls, instead of running on a more expensive and difficult to reserve GPU node.
::: <code>module load StdEnv/2023 ansys/2025R2.04</code>
::: <code>runwb2</code>


<!--T:24-->
To start Fluent from within Workbench, click on ''Fluid Flow (Fluent)'' or ''Fluent with Fluent Meshing'' in the left-hand ''Analysis'' menu, and click on ''Setup'' in the centre canvas ''Fluid Flow (Fluent)'' popup.  Once the ''Fluent Launcher'' selector panel popup appears, click on the ''Environment'' tab and copy/paste the following environment variable settings:
::: <code>I_MPI_HYDRA_BOOTSTRAP=ssh</code> &nbsp;&nbsp;&nbsp;&nbsp; (required on the Nibi cluster only)
::: <code>HOOPS_PICTURE=opengl2-mesa</code> &nbsp;&nbsp; (optional for 2025R1 or newer)
::: Click on the ''Start'' button.


<!--T:25-->
<b>Compute node (with GPU requested)</b>


<!--T:26-->
If accelerated graphics are required on the Nibi cluster, choose t4 (15GB) from the GPU selector pulldown list for your OnDemand desktop session.  Doing this will ensures that the environment variables used by VirtualGL to enable accelerated OpenGL graphics calls are automatically set up inside your deskop environment for the current session.  Once your desktop appears, open a terminal window and start Workbench as follows
::: <code>module load StdEnv/2023 ansys/2025R2.04</code>
::: <code>runwb2</code>


<!--T:27-->
To start Fluent from within Workbench, click on ''Fluid Flow (Fluent)'' or 'Fluent with Fluent Meshing'' in the left-hand ''Analysis'' menu, and click on ''Setup'' in the centre canvas ''Fluid Flow Fluent'' popup.  Once the ''Fluent Launcher'' selector panel popup appears, click on the ''Environment'' tab and copy/paste the following environment variable settings.
::: <code>I_MPI_HYDRA_BOOTSTRAP=ssh</code> &nbsp;&nbsp;&nbsp; (required on the Nibi cluster only)
::: <code>HOOPS_PICTURE=opengl2</code> &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;(optional for 2025R1 or newer)
::: Click on the ''Start'' button.

::: Click to load ansys/2025R1 (or newer version) in the Desktop left hand side menu
::: Click on the ''Workbench (VNC)'' icon located in the JupyterLab desktop centre window.
:::: If the graphics of any application (such as Fluent) started within Workbench
:::: appear unusable because they seem corrupted, try carrying out the following
:::: steps.  They will create a custom runwb2 desktop icon so that Workbench
:::: can be started in Mesa mode.  If one of the applications that you will be starting 
:::: in Workbench is Fluent, you may also try setting
:::: <code>HOOPS_PICTURE=opengl2-mesa</code> variable in the Fluent Launcher window when the Fluent launcher starts.
:::: <code>HOOPS_PICTURE=opengl2-mesa</code> variable in the Fluent Launcher window.
::: To proceed, exit Workbench and open a terminal window.  Copy/paste the following
::: command into the ''Remote Clipboard'' located in the top right corner of your Jupyter desktop. 
::: Now the commands can be pasted into the terminal i.e.
::: <code>cd ~/Desktop; cp -p $(realpath workbench.desktop) workbench-mesa.desktop</code>
::: Open the newly created file in a text editor such as nano by doing the following:
::: <code>nano ~/Desktop/workbench-mesa.desktop</code>.  Change all instances of <code>runwb2</code>
::: to  <code>runwb2 -oglmesa</code> and exit the editor, saving the changes.  Now REFRESH
::: the Jupyter desktop by pressing the key combination <i>control-R</i>.  The new icon should now
::: appear in the desktop along with the original Workbench icon. Double-click on it to start Workbench.
::: The new icon will persist for future sessions until manually deleted with the command
::: <code>rm -f ~/Desktop/workbench-mesa.desktop</code>.
